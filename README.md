# Dvorik — склад, график и админка на новой архитектуре

Dvorik объединяет Telegram-бота и веб-админку для оффлайн-магазина. Проект
переписан на модульную архитектуру под пространством имён `dvorik/`, использует
Python 3.12, aiogram 3.7, Flask 3.0 и SQLite в режиме WAL. Этот README описывает
актуальные команды, конфигурацию и точки расширения.

## Ключевые возможности

- **Телеграм-бот** для продавцов и администраторов: карточки товаров, движение
  между локациями, инвентаризация, inline-поиск и сценарии графика.
- **Импорт поставок** из CSV/XLS с нормализацией данных, антидубликатами и
  журналом `import_log`.
- **Инвентаризация и склад** с транзакционными перемещениями, разграничением по
  локациям и событиями для уведомлений.
- **График смен** с календарём `/sched`, заявками на обмен и PNG/PDF-отчётами.
- **Веб-админка** (Flask) для таблиц SQLite, поставок, уведомлений и панели
  супер-админа.
- **Плагины**: единые реестры виджетов, меню и aiogram-роутеров позволяют
  расширять систему без форка.

## Структура репозитория

```
dvorik/
  app.py            # Composition root (create_system)
  core/             # Config, события, планировщик, реестры, загрузка плагинов
  db/               # Подключение SQLite, миграции, registry запросов
  domain/           # Dataclasses и контрактные интерфейсы репозиториев
  repo/             # Реализации репозиториев поверх SQLite
  services/         # Бизнес-логика: склад, уведомления, импорт, расписание
  admin/            # Flask-приложение, blueprints, виджеты
  bot/              # Aiogram-приложение, колбэки, клавиатуры, роутеры
  plugins/          # Пример и пользовательские плагины
```

Дополнительные подробности смотрите в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Требования

- Python 3.12.
- SQLite с поддержкой WAL и (опционально) FTS5.
- Зависимости из `requirements.txt` (aiogram, Flask, pandas, openpyxl, xlrd/xlrd2,
  Pillow и др.).
- Telegram-бот с токеном, супер-админ (`SUPER_ADMIN_ID`) и его username.

## Конфигурация

Настройки считываются модулем `dvorik.core.config` в следующем порядке
приоритетов: переменные окружения → `.env` → `config.json` → значения по
умолчанию. Минимальный `config.json`:

```json
{
  "BOT_TOKEN": "123:abc",
  "SUPER_ADMIN_ID": 123456789,
  "SUPER_ADMIN_USERNAME": "@username",
  "DB_PATH": "data/marm.sqlite3"
}
```

Каталоги `data/`, `media/`, `reports/`, `data/uploads/normalized` и `media/photos`
создаются автоматически, если отсутствуют. Значения можно переопределить через
переменные окружения (`DATA_DIR`, `MEDIA_DIR`, `REPORTS_DIR`, `PAGE_SIZE` и т.д.).

## Запуск

### Быстрый старт (macOS/Linux)

Скрипты в корне проекта собирают виртуальное окружение и запускают новые точки
входа:

```bash
./run_bot.command      # python -m dvorik.bot
./run_admin.command    # python -m dvorik.admin
```

Обе команды переиспользуют `venv/`, устанавливают зависимости и поднимают бота
или Flask-сервер на порту `ADMIN_PORT` (по умолчанию 8000).

### Ручной запуск

```bash
python3.12 -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -U pip
pip install -r requirements.txt

# Telegram-бот
python -m dvorik.bot

# Админка (Flask dev server)
python -m dvorik.admin
# или низкоуровневая фабрика без обвязки
python -m dvorik.admin.server
```

После старта авторизуйтесь в боте как супер-админ — появится панель назначения
ролей и меню супер-администратора.

### Docker

```
cp .env.example .env
# заполните BOT_TOKEN, SUPER_ADMIN_ID, SUPER_ADMIN_USERNAME и при необходимости ADMIN_PORT/DB_PATH
docker compose up -d --build
```

Стек поднимает два сервиса (`bot`, `admin`) с общими volume `./data`, `./media`,
`./reports`. Остановить: `docker compose down`.

## Мониторинг и проверки

- `GET /health` — быстрый ответ «жив ли процесс» от Flask-приложения.
- `GET /ready` — углублённая проверка: выполняет `SELECT 1` в SQLite и убеждается,
  что плагины загружены.
- Команда бота `/ping` — сообщает время последнего тика планировщика, помогая
  удостовериться, что фоновые задания продолжают работать.

Docker Compose использует `/ready` для встроенного `healthcheck`, поэтому
оркестратор перезапустит контейнер при потере подключения к БД или провале
регистрации плагинов.

## Роли и супер-админ

В таблице `user_role` три основных уровня:

- **Super admin** — задаётся в конфиге, управляет ролями, меню, реестром SQL
  запросов, виджетами и расписанием.
- **Admin** — полный доступ к поставкам, инвентаризации, уведомлениям и отчётам.
- **Seller** — операции с остатками, инвентаризация, личный график.

Супер-админка валидирует JSON-конфигурации экземпляров виджетов по схеме,
указанной в каталоге. При несоответствии сохранение блокируется, а в форме
появляется сообщение с причиной — так проще исправить настройки сразу в UI.
В рабочей панели такие экземпляры подхватывают безопасную заглушку, а ошибки
пишутся в журнал.

Новые пользователи проходят мастера регистрации в боте. Заявки попадают в
`registration_request`, а супер-админ получает уведомление и может назначить
роль прямо из Telegram.

## Плагины и реестры

Система использует централизованные реестры (`MenuRegistry`, `WidgetRegistry`,
`BotRouterRegistry`, `JobRegistry`, `QueryRegistry`). Модуль
`dvorik.core.plugins` автоматически загружает модули из `dvorik/plugins` и даёт
хелперы для регистрации.

Пример `dvorik/plugins/example` показывает, как:

- добавить виджет «Top SKUs» на главную страницу админки и в каталог виджетов;
- создать пункт меню в разделе супер-админа;
- зарегистрировать aiogram-роутер с командой `/topskus`.

Плагины могут также добавлять задачи планировщика, дополнять меню бота и
расширять таблицу запросов.

## Тестирование

`pytest` покрывает ядро (события, колбэки, реестр SQL, стратегии импорта,
складской сервис). Запуск:

```bash
pytest
```
