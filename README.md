# Dvorik — складской Telegram-комбайн

Телеграм-бот сопровождает работу оффлайн-магазина: фиксирует остатки по локациям, принимает поставки, выдаёт отчёты, ведёт график продавцов и синхронизируется с лёгкой веб-админкой. Проект написан на Python 3.12 и использует aiogram 3.7, Flask 3.0 и SQLite с режимом WAL.

## Возможности с высоты птичьего полёта
- **Телеграм-бот** для продавцов и администраторов: карточки товаров, движение между локациями, кнопки быстрого списания в зал, сценарии инвентаризации и inline-поиск с режимами `NEW`, `INC`, `INV`, `ADM`.
- **Импорт поставок** из CSV/XLS с нормализацией, защитой от дубликатов по SHA‑256 и автозаполнением SKU (таблица `import_log`).
- **Инвентаризация** с выбором локации, пагинацией остатков и атомарными корректировками (в минус уйти нельзя).
- **Маршруты перемещения** через контекст «откуда → куда», а также прямое редактирование остатков или возвраты на «HALL».
- **Фотографии и карточки**: загрузка по `file_id`, кеширование в `media/photos`, сжатие JPEG ½ качества и управление локальными именами.
- **Уведомления** о нулевых остатках, последней пачке и новых поступлениях на склад — мгновенные и в ежедневной сводке (21:10). Архивация «залежавшихся» товаров выполняется автоматически.
- **График продавцов** с персональным календарём `/sched`, заявками на обмен сменами, админским режимом и генерацией PNG/PDF‑отчёта на два месяца.
- **Веб-админка** (Flask) для просмотра/редактирования SQLite-таблиц, работы со складами, архивом, картами товаров и расписанием.
- **Стресс и QA**: `stress_test.py` имитирует массовые поставки, перемещения и уведомления; есть `pytest` для модулей импорта и GitHub Actions для CI/CD.

## Архитектура и структура репозитория
```
app/                # Telegram-бот, хендлеры, сервисы и конфигурация
admin_ui/           # Flask-приложение с Bootstrap-шаблонами
scripts/xls_to_csv.py  # CLI-конвертер .xls → CSV
stress_test.py      # Интеграционный стресс-скрипт
requirements.txt    # Основные зависимости
Dockerfile          # Базовый образ Python 3.12 + проект
docker-compose.yml  # Стек из bot + admin с общими volume
```
Ключевые узлы кода:
- `app/main.py` — точка входа бота: инициализация схемы, запуск поллинга и ночного планировщика (рассылка дайджеста и зачистка архива).
- `app/config.py` — поиск `config.json`, настройка путей (`data/`, `media/photos`, `reports/`), считывание токена и супер-админа, выбор БД с учётом переменных окружения.
- `app/db.py` — создание SQLite-схемы (WAL, FTS5 при наличии), миграции и сидирование локаций `SKL-*`, `DOMIK`, `HALL`, `COUNTER` («за стойкой»).
- `app/routers.py` и `app/handlers/*` — сценарии Телеграм-бота: поставка, отчёты, инвентаризация, перемещения, график, регистрацию, уведомления.
- `app/services/*` — бизнес-логика (импорт, складские операции, уведомления, архив, расписание, фотографии и др.).
- `admin_ui/server.py` + шаблоны — веб-интерфейс на Flask 3: браузер таблиц, карточки, отчёты, инвентаризация и расписание.

## Требования
- Python 3.12 и `pip`. Скрипты `run_bot.command`/`run_admin.command` ищут подходящий интерпретатор и создают `venv`.
- Зависимости из `requirements.txt`: aiogram 3.7, pandas, openpyxl, xlrd/xlrd2, Pillow и Flask.
- SQLite 3 с поддержкой WAL; модуль FTS5 подключится автоматически, если доступен в сборке.
- Телеграм-бот с токеном и учёткой супер-администратора.

## Конфигурация
Файл `config.json` можно положить рядом с проектом, либо указать через переменную окружения `CONFIG_PATH`. Приоритет чтения (см. `app/config.py`):
1. `CONFIG_PATH`.
2. `/Users/nikitamysnik/Desktop/progs/config.json` (продакшн-путь).
3. Локальный `config.json` в репозитории.

Минимальное содержимое:
```json
{
  "BOT_TOKEN": "123:abc",
  "SUPER_ADMIN_ID": 123456789,
  "SUPER_ADMIN_USERNAME": "@username",
  "DB_PATH": "data/marm.sqlite3"        // необязательно
}
```
Значения можно переопределять переменными окружения. При старте автоматически создаются каталоги `data/`, `data/uploads/normalized`, `media/photos`, `reports/`. Путь к базе (`DB_PATH`) выбирается в таком порядке: env → config → продакшн-файл → `data/marm.sqlite3` → `data/marm.db` (совместимость).

## Локальный запуск
### Быстрый старт (macOS)
```bash
./run_bot.command
```
Скрипт создаёт/переиспользует `venv`, подтягивает зависимости и запускает `python -m app.main`.

### Универсальный запуск (Linux/macOS/Windows)
```bash
python3.12 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -U pip
pip install -r requirements.txt
python -m app.main
```
После запуска напишите боту `/start` с аккаунта супер-админа — появится «Панель администратора» для назначения ролей.

### Веб-админка
```bash
./run_admin.command
# или вручную
python -m admin_ui
```
По умолчанию UI слушает `http://127.0.0.1:8000`. Переменные `ADMIN_HOST`/`ADMIN_PORT` позволяют открыть доступ в сети.

### Одновременная работа
Бот и админку запускают в отдельных терминалах. Оба процесса используют одну и ту же SQLite-базу и директории.

## Запуск в Docker
1. Скопируйте `.env.example` → `.env` и заполните `BOT_TOKEN`, `SUPER_ADMIN_ID`, `SUPER_ADMIN_USERNAME`, при необходимости `ADMIN_PORT` и `DB_PATH`.
2. Соберите и поднимите сервисы:
   ```bash
   docker compose up -d --build
   ```
   Стек состоит из двух контейнеров (`bot`, `admin`) с общими volume `./data`, `./media`, `./reports`.
3. Админка будет доступна по `http://<host>:<ADMIN_PORT>`. Логи: `docker compose logs -f bot` / `admin`.
4. Остановить: `docker compose down`.

## Роли и доступ
- **Super admin** — задаётся в конфиге, видит все панели и может управлять администраторами.
- **Admin** — полный доступ к поставкам, инвентаризации, уведомлениям, отчётам, расписанию.
- **Seller** — чтение карточек и остатка, базовые перемещения, личный календарь.

Пользователь без роли может отправить сообщение боту: запускается мастер регистрации (`app/handlers/registration.py`), собирающий имя и уведомляющий админов. Решение (`админ`/`продавец`/`отклонить`) приходит кнопками в Telegram, а заявки хранятся в таблице `registration_request`.

## Повседневные сценарии
### Импорт поставок
1. «Поставка → 📄 Загрузить счёт (CSV/XLS)» принимает исходные файлы.
2. Модуль `app/services/imports.py` определяет заголовки, чистит названия, фильтрует услуги, нормализует количество и сохраняет промежуточный CSV в `data/uploads/normalized`.
3. SHA‑256 исходника используется для антидубля (таблица `import_log`). В журнал записываются путь, поставщик, номер счёта и список товаров.
4. Новые товары появляются в `product` с `is_new=1`, остаток зачисляется на `SKL-0`, отправляется CSV-отчёт.
5. Предпросмотр и мэппинг поставки сохраняются в таблице `import_session`, поэтому после перезапуска админки процесс можно продолжить без повторной загрузки файла.

### Карточки и перемещения
- Inline-поиск (`@бот INV …`, `NEW`, `INC`, `ADM`) строит карточки и команды `/open_<id>`, `/admin_<id>`.
- Карточка показывает суммарный остаток, разрез по локациям и быстрые действия: «В зал (−1)», «Маршрут», «Всё из SKL‑0 → X» и т.д.
- Перемещения (`app/services/stock.py`) отслеживают остаток, не позволяют уйти в минус и записывают события в `event_log` для уведомлений.

### Инвентаризация
- «Инвентаризация» открывает список локаций (`locations_2col_keyboard`).
- Для каждой локации показывается страница остатков с кнопками `−1/+1`, поддерживается добавление товара через inline-поиск.
- Из карточки инвентаризации доступны предустановленные дельты (−5/−1/+1/+5) и действия «➕ Добавить» / «➖ Убавить» — всегда внутри транзакции.

### Расписание продавцов
- Команда `/sched` показывает календарь месяца с навигацией и кнопкой «Таблица» для PNG/PDF на два месяца.
- Пользователь может предложить обмен сменой: выбирает дату, свободного коллегу и отправляет заявку; целевой сотрудник подтверждает или отклоняет.
- Админы управляют открытыми днями, назначениями и якорем генерации графика (`app/services/schedule.py`). Алгоритм учитывает 3–4 продавцов и не перезаписывает вручную заполненные даты.

### Уведомления и архив
- Типы событий: `zero`, `last`, `to_skl`. Режимы — `off` / `daily` / `instant` на пользователя и тип.
- Мгновенные уведомления отправляются через `notify_instant_*`, а ежедневная сводка формируется `send_daily_digests` и включает списки законченных товаров и пополнений.
- `app/services/archival.py` каждые сутки архивирует товары без остатков и рестоков старше N дней, снимая их из поисковой выдачи.

### Отчёты и вспомогательные функции
- Отчёты «Заканчиваются», «Нулевой остаток», «В достатке», «Все», «Архив» выгружаются в CSV (`reports/`).
- «График → Таблица» рендерит PNG и, при возможности, PDF (Pillow) и сохраняет их также в `reports/`.
- CLI `scripts/xls_to_csv.py` помогает конвертировать старые `.xls` в CSV.

### Фотографии
- `app/services/photos.py` скачивает фото по `file_id`, уменьшает размер вдвое и сохраняет JPEG с качеством `PHOTO_QUALITY` (85) в `media/photos`.
- При открытии карточки бот проверяет локальный кеш; если файла нет, скачивает повторно и обновляет `product.photo_path`.

## База данных
Основная схема (`app/db.py`):
- `product` — артикул, названия, флаги `is_new`, `archived`, время последнего поступления, пути к фото.
- `location` — коды локаций и типы (`SKL`, `DOMIK`, `HALL`, `COUNTER` — «за стойкой»).
- `stock` — остатки по локациям (qty_pack) с кэшированными именами.
- `user_role` — роли пользователей; `user_notify` — настройки уведомлений.
- `event_log` — журнал событий для отчётов и уведомлений.
- `import_log` — история поставок (хэши, поставщик, счёт, JSON позиций, отметки об откате).
- Таблицы расписания: `schedule_day`, `schedule_assignment`, `schedule_transfer_request`, `schedule_anchor`.
- `registration_request` — заявки на доступ.
- `product_fts` — виртуальная FTS5-таблица для поиска; триггеры синхронизируют изменения.

При запуске применяются миграции (`ALTER TABLE ...`) и сидируются стандартные локации. Все операции выполняются в транзакциях, `busy_timeout=10000` уменьшает вероятность `database is locked`.

## Веб-админка
Приложение Flask (`admin_ui/server.py`) использует Bootstrap-шаблоны:
- Домашняя страница с плитками таблиц и быстрым переходом к просмотру/редактированию.
- Просмотр таблицы с пагинацией и скрытием «технических» колонок.
- Карточки товара с фотографиями и остатком.
- Экран инвентаризации и управляемый список локаций.
- Раздел расписания с визуализацией смен, статусами заявок и ручными правками.

UI читает ту же SQLite-базу, поэтому правки мгновенно попадают в бота.

## Тестирование и автоматизация
- `pytest` запускает модульные тесты (см. `tests/test_imports.py`) для разбора Excel.
- `stress_test.py` использует заглушки aiogram, создаёт отдельную БД, импортирует CSV, выполняет случайные перемещения, инвентаризации и уведомления — ищите `OVERALL: OK`.
- GitHub Actions (`.github/workflows/cicd.yml`) выполняет линтер/тесты и собирает Docker-образ `msnq/dvorik`, после чего может деплоить через SSH.

## Частые вопросы
- **Python < 3.12?** Установите новую версию (macOS: `brew install python@3.12`) или используйте Docker.
- **FTS5 отсутствует?** Поиск переключится на `LIKE`, функциональность сохранится.
- **Ошибки чтения `.xls`?** Убедитесь, что `xlrd`/`xlrd2` установлены; можно конвертировать через `scripts/xls_to_csv.py`.
- **`database is locked`?** Подождите пару секунд или перезапустите процесс — включены WAL и `busy_timeout`.
- **Нет доступа у нового сотрудника?** Проверьте «Панель администратора → Заявки на доступ» и назначьте роль.
